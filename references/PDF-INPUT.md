# PDF 输入桥接指南

> **本 skill 不直接处理 PDF**——`article.md` 必须是 markdown 文本
> （详见 SKILL.md Phase 1.1）。但 Claude Code 的 `Read` 工具原生支持
> PDF 解析（自动按页转文本），所以可以**做一步最小桥接**后，让论文 /
> 报告 / 白皮书 / eBook 这类源料走通整条流水线。

## 桥接流程（4 步）

```
PDF 文件
  ↓ 1. Read 工具读取（按页转文本）
  ↓ 2. 清洗：去页眉页脚 / 修复断行 / 提取图注与表格
  ↓ 3. 写入 article.md（保留为唯一事实源）
  ↓ 4. 走 SKILL.md 原生 Phase 1.1 起的全部流程
```

### 步骤 1 — `Read` 工具读 PDF

**单次读**（≤ 20 页）：

```python
# agent 内部判断：直接 Read 整文件
read_file(path="paper.pdf")
```

**分批读**（> 20 页，强制分页）：

```python
# 必须传 pages 参数；否则 Read 会拒读
read_file(path="paper.pdf", pages="1-20")
read_file(path="paper.pdf", pages="21-45")
```

> **不要试图把 100 页 PDF 一次读完**——除了 Read 工具的硬限制，
> 一次性全文进上下文也会污染后续 script.md 抽取的信息保留度判断。

### 步骤 2 — 清洗

Read 工具返回的是「页面级纯文本」，通常带这些问题：

| 问题 | 处理方式 |
|---|---|
| 页眉页脚 / 页码 / DOI 条 | 整行删 |
| 跨页断词（"trans- former" → "transformer"） | 合并 |
| 表格被压平成逗号串 | 还原成 markdown 表格 |
| 公式变 LaTeX 源码 | 保留为 `$...$`（outline 信息池会用到） |
| 图表位置只留"Figure 3"字样 | 补一句描述（见下文「图像 / 图表」） |
| 双栏排版左右栏粘连 | 用空行 / 标题切分还原段落顺序 |

### 步骤 3 — 写 `article.md`

把清洗后的文本落盘到 `article.md`，**与 SKILL.md 约定的目录一致**：

```
my-video/
├── paper.pdf           # 原始 PDF（保留！出问题好回查）
├── article.md          # 提取后的纯文本 ← 关键
├── script.md           # 后面的流程都从这里出
└── outline.md
```

`article.md` 顶部建议加 1 段元信息（不计入字数）：

```markdown
# <论文 / 报告标题>

> 来源：paper.pdf（<N> 页 / <作者> / <会议或期刊>）
> 提取方式：Read 工具逐页转文本 + 人工清洗
> 提取日期：<YYYY-MM-DD>
> 注意事项：图 N、表 M 的描述已在文中标出
```

### 步骤 4 — 走原生流程

从 SKILL.md 的 Phase 1.1 重新开始。此刻 `article.md` 已经是合法输入，
**skill 不会再感知到 PDF 存在过**。

## 边界情况（必须告诉用户的事）

### A. 图像 / 截图 / 流程图

**问题**：Read 工具对 PDF 里的栅格图基本无能为力（返回的只有图注文字）。

**处理**：

1. 让用户先把图手动导出成 PNG（学术论文通常能从出版社 PDF 里复制图，
   或重新截图）
2. 放进 `assets/figures/fig-N.png`
3. `article.md` 里在原图位置插入「图占位」：

   ```markdown
   ![<一段可读的图描述>](assets/figures/fig-N.png)
   ```

4. **信息池里要标**：`<图 N：XXX>`，chapter agent 才知道画面要挂
   哪个文件（见 SKILL.md 信息池约定）

> 这是论文类视频最容易翻车的点。**没有真图 = 屏幕是空白或泛指**——
> 在 Checkpoint Plan 的"4. 真素材怎么准备"那一步，**主动告诉用户**
> 「本视频需要 N 张图，请按 assets/figures/fig-N.png 命名提供」。

### B. 公式 / 数学符号

**问题**：Read 工具会尽力把公式转成 LaTeX，但识别率约 60~80%（取决于
PDF 是文本型还是扫描型）。

**处理**：

- 行内公式：保留为 `$...$`（信息池引用时直接挂）
- 行间公式：保留为 `$$...$$`
- 识别错的（明显乱码）→ 回到 `paper.pdf` 对应页肉眼校对

### C. 扫描件 PDF（无文本层）

**问题**：很多老论文 / 内部报告是扫描件，Read 工具**读不出**文本，
只会返回空或乱码。

**处理路径**：

1. 先 `Read` 试一次，**主动告诉用户**结果：「这是扫描件，文本层为空」
2. 让用户做选择：
   - **a) 找原文文本版**（期刊网站 / arXiv 几乎都有 HTML 版）
   - **b) 走 OCR 兜底**（skill 本身不带 OCR 工具；可用外部 `ocrmypdf` /
     Adobe / 微信图片转文字）—— **OCR 后的文本同样要人工校对**，
     公式 / 引用 / 数字错误率较高
   - **c) 放弃 PDF，改用摘要 / 笔记作为 article.md**（⚠️ 信息保留度
     会从源头打折扣，要主动告知用户）

### D. 加密 / 受 DRM 保护

**问题**：DRM PDF 完全打不开。

**处理**：让用户先解密（合法授权范围内）。**不要**试图绕过——既不
可能成功，也不应该。

### E. 超长 PDF（> 50 页）

**问题**：即使分页读，全文进上下文也会挤占后续 script.md 抽取的
注意力。

**处理**：

- **优先**：让用户标出**本次视频要覆盖的章节 / 页码范围**
  （不是全文都做）
- **次优**：让用户用一段话描述"重点是哪几节"，agent 只读那些
- **兜底**：分批读全文 → 但要主动告知用户「原 X 页，全文进上下文
  会让后续 script 抽取的判断变粗，**建议拆成 2~3 集视频**」

## 与 skill 其他部件的衔接

| 阶段 | PDF 桥接的影响 |
|---|---|
| Phase 1.1 识别用户输入 | 在「用户给的东西」表格里**新增一行**：「PDF / 论文 PDF」→ 触发本指南 4 步桥接 |
| Phase 1.2 一次产出 script.md + outline.md | `article.md` 一旦落盘，**后续流程完全相同**——双源原则照常生效 |
| Checkpoint Plan「4. 真素材怎么准备」 | 主动列 PDF 中的图 / 表清单（按文中 Figure / Table 编号），让用户决定哪些用真图哪些用占位 |
| Phase 2.1 脚手架 | 无影响——脚手架只关心 theme，不关心 article 来源 |
| Phase 2.4 实现单章 | 信息池里的「`<图 N：XXX>`」会被 chapter agent 当作 `assets/figures/fig-N.png` 引用；缺图时画面会留白，**提前在 Checkpoint Plan 锁定** |
| Phase 3 音频合成 | 无影响——只看 narrations.ts |

## 自检清单（PDF 桥接完成时过一遍）

- [ ] 原始 PDF 还在工作目录（**不删**——出问题回查用）
- [ ] `article.md` 顶部有元信息块（来源 / 提取方式 / 注意事项）
- [ ] 关键事实（数字 / 引用 / 表格 / 公式 / 论断）**逐项对得上**原文
- [ ] 图表位置已插入 `assets/figures/fig-N.png` 引用（图本身用户另提供）
- [ ] 信息保留度预估：清洗后文本字数 / 原始 PDF 可读字数 ≥ 80%
  （PDF 桥接的额外损耗不能超过 20%）
- [ ] 扫描件 / 加密 / 超长 三种异常情况之一时，**Checkpoint Plan
  之前**已主动告诉用户选了哪条路
